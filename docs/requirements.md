# mock-humanoid 需求文档

状态：Draft
版本：0.15
日期：2026-07-22

## 1. 文档目的

本文档定义 `mock-humanoid` 第一版可交付产品的范围和验收标准。

`mock-humanoid` 是运行在单个 Docker 容器中的网页人形机器人模拟器。浏览器通过 Stardust Realtime 获得语音对话和工具调用能力；机器人导航、操作物体、人物跟随、动作和表情均在浏览器内的模拟世界中执行。

本文档是第一版实现的产品契约。未在本文档中定义的注册、登录、多用户、数据库、历史记录和云端场景管理能力均不属于第一版范围。

## 2. 产品目标

### 2.1 核心目标

1. 用户打开页面即可进入模拟器，不经过注册、登录或鉴权页面。
2. 用户可以连接 Stardust Realtime，通过麦克风或文本与机器人对话，并听到模型的实时语音输出。
3. Stardust 可以通过 function call 调用 8 个本地机器人技能。
4. 导航过程同时显示在 2D 导航地图和 3D 点云视图中，两者的机器人位置、朝向、规划路线和任务状态保持一致。
5. 3D 地图中的机器人必须使用宇树人形机器人 G1 的 URDF 模型和配套 mesh 资源，不使用通用人形替代模型。
6. 操作、交接、跟随、动作和表情具有明确、可观察的模拟反馈。
7. `group_id`、`robot_id` 和 Stardust 服务地址由 Docker 环境变量提供。
8. 用户可以在页面中编辑并应用 `session.update` JSON；系统只校验 JSON 语法和顶层对象类型，不校验字段内容是否合理。
9. 所有业务状态仅存在于当前页面内存中，刷新页面后恢复初始状态。
10. 用户可以在页面内新增临时位置点、按顺序编排临时路线，并手动命令机器人前往位置点或执行路线。

### 2.2 非目标

第一版不包含：

- 注册、登录、账号、角色或权限。
- 数据库、文件存储、云存储、浏览器持久化或操作历史查询。
- 多用户协作、机器人占用锁或并发控制。
- 真实 ROS、SLAM、机械臂、底盘、相机或 LiDAR 设备接入。
- 固定障碍、地图边界、人物、物体、放置面编辑或场景发布。
- 对用户填写的 session 配置进行模型、字段、取值范围或业务合理性校验。
- 通用物理引擎精确仿真、碰撞动力学或机器人安全认证。
- 移动端原生应用。

## 3. 用户与使用假设

### 3.1 目标用户

- 需要演示 Stardust 具身智能工具调用的产品、售前和研发人员。
- 需要验证 session 配置、function call 参数和本地执行反馈的调试人员。

### 3.2 使用假设

- 同一时刻只有一个用户使用一个页面实例。
- 页面运行在桌面浏览器中，用户已允许麦克风权限。
- 容器启动前已经正确设置 Stardust 环境变量。
- 模拟场景、人物、物体、内置点位和内置巡逻路线随前端资源一起发布；用户可在当前页面内存中叠加自定义点位和路线。
- 页面刷新等同于创建一台新的模拟机器人和一个新的模拟世界。

第一版只有一个主页面，不设置登录页、列表页和后台管理页。

桌面布局的外层高度固定为浏览器可视高度，不允许消息、事件或场景控制内容撑高整个页面：

```text

│ 顶栏（固定）                                      │
├──────────────────────────┬────────────────────────┤
```

- `workspace`、主模拟列和右侧列都必须允许 Flex/Grid 子项收缩并裁剪外溢，2D/3D Canvas 高度只能来自当前可见主视图区，不能由右侧内容高度反向撑开。
- 对话消息、任务事件和场景控制分别使用各自的内部纵向滚动容器；标签栏和对话输入框不随消息滚动。
- 对话列表位于底部附近时，新消息或流式文本自动跟随到最新内容；用户主动向上滚动查看历史后不强制拉回，切回“对话”标签时恢复到最新消息。

### 5.2 设置抽屉

```text
页面
└─ 设置抽屉（覆盖在页面右侧；打开后焦点进入 JSON 编辑器）
   ├─ 只读运行配置：Stardust URL、group_id、robot_id
   ├─ session.update JSON 编辑器
   ├─ JSON 校验结果或 Stardust 返回错误
   └─ [格式化] [恢复本页初始值] [取消] [应用]
```

设置抽屉关闭后焦点返回“设置”按钮。抽屉内草稿仅在本次打开期间存在：点击“取消”、按 `Esc` 或点击遮罩均关闭抽屉并丢弃未应用修改；下次打开时重新载入当前待连接配置或最近一次已生效配置。“恢复本页初始值”只把编辑器草稿替换为项目内置 session 示例，不立即发送 `session.update`，用户仍需点击“应用”。

### 5.3 核心交互

| 输入 | 作用域 | 行为 |
|---|---|---|
| 点击“连接” | 顶部栏 | 校验当前 session JSON，建立 Realtime 连接并发送 session 配置 |
| 点击“断开” | 顶部栏 | 停止录音与播放，关闭 Realtime；模拟世界不重置 |
| 点击麦克风 | 对话区 | 在持续收音和静音之间切换 |
| `Enter` | 文本输入 | 发送文本；`Shift+Enter` 换行 |
| 点击 2D/3D/双视图 | 主视图区 | 切换呈现方式，不断开 Realtime，不重置任务 |
| 点击“停止当前任务” | 任务栏 | 取消正在运行的移动或操作任务 |
| 点击“重置模拟世界” | 任务栏 | 先二次确认，再恢复初始机器人、人物和物体状态；Realtime 保持连接 |
| 点击“应用” | 设置抽屉 | 解析 JSON，合并内置 tools，发送新的 `session.update` |
| 新增位置点 | 场景控制 | 校验名称、坐标和可达性后加入当前页面的地点名称域 |
| 前往 | 场景控制的位置点 | 通过与 `navigate_to` 相同的调度路径启动点到点导航 |
| 编排并保存路线 | 场景控制 | 按用户选择顺序保存至少两个位置点组成的临时循环路线 |
| 执行路线 | 场景控制的路线 | 通过与 `start_patrol` 相同的调度路径循环执行，直到停止或被抢占 |
| 鼠标滚轮/触控板滚动 | 对话消息区 | 只滚动消息历史；可到达最早和最新消息，不移动整个页面或改变 2D/3D Canvas 高度 |

Realtime 处于错误状态时，顶部主按钮显示“重新连接”；其行为与初始“连接”相同。

### 5.4 响应式要求

- `>= 1280px`：默认双视图，右侧同时显示对话和事件。
- `1024px–1279px`：主视图默认单视图，2D/3D 通过标签切换；右侧栏保留。
- `< 1024px`：主视图、对话和事件纵向排列，所有核心操作仍可使用。
- 第一版不对窄屏手势操作和移动端性能作专项优化。

## 6. 启动与运行配置

### 6.1 Docker 运行要求

- 项目必须提供可构建的 `Dockerfile`。
- 单个容器同时提供网页静态资源和运行时配置接口。
- 默认监听容器内 `3000` 端口，并允许通过 `PORT` 覆盖。
- `GET /healthz` 在 Web 服务可接受请求时返回 HTTP 200。
- 容器文件系统不得被用于保存 session 配置、对话或模拟状态。

### 6.2 环境变量

为与现有 playground 配置习惯一致，第一版采用以下变量：

| 环境变量 | 必填 | 默认值 | 用途 |
|---|---|---|---|
| `VITE_STARDUST_BASE_URL` | 否 | `wss://stardust.ticos.cn` | Stardust 服务根地址 |
| `VITE_STARDUST_GROUP_ID` | 是 | 无 | 连接参数 `group_id` |
| `VITE_STARDUST_ROBOT_ID` | 是 | 无 | 连接参数 `robot_id` |
| `PORT` | 否 | `3000` | 容器内 Web 服务端口 |

要求：

- 变量在容器启动时读取，不要求重新构建镜像。
- 前端通过只读运行时配置接口获取这些值。
- `group_id` 和 `robot_id` 不在页面中编辑。
- 缺少必填值时页面仍可打开，但“连接”不可用，并明确列出缺少的变量。
- 页面不提供保存或修改容器环境变量的能力。

`VITE_` 前缀仅用于沿用现有 playground 的变量名；这些变量由 Web 服务在容器运行时读取并通过接口返回，不按 Vite 编译期替换处理。

### 6.3 Realtime URL

连接地址基于服务根地址生成：

```text
{baseUrl}/realtime
  ?terminal_secret=X-Tiwater-Debug
  &group_id={VITE_STARDUST_GROUP_ID}
  &robot_id={VITE_STARDUST_ROBOT_ID}
```

`X-Tiwater-Debug` 仅用于现有 group/robot 调试连接约定，不作为用户登录或页面鉴权功能呈现。该值会出现在浏览器可见的 WebSocket URL 中，只允许用于内网、开发或演示环境，不得作为生产鉴权方案。若后续版本用于生产环境，必须另行设计正式终端鉴权或由后端签发短期凭据；该能力不属于第一版。

### 6.4 运行时配置接口

`GET /api/runtime-config` 返回：

```json
{
  "baseUrl": "wss://stardust.ticos.cn",
  "groupId": "demo-group",
  "robotId": "mock-humanoid-01",
  "missingRequired": []
}
```

契约：

- `baseUrl`、`groupId`、`robotId` 始终存在且类型为 string；未配置的值返回空字符串。
- `missingRequired` 是缺失的必填环境变量名称数组，只可能包含 `VITE_STARDUST_GROUP_ID` 和 `VITE_STARDUST_ROBOT_ID`。
- 响应不得包含 API key、真实终端密钥或其他进程环境变量。
- 接口返回 `Cache-Control: no-store`，但服务端不得因此创建任何会话存储。
- 选择 `/api/runtime-config` 是为了明确其职责是容器运行时配置；不复用参考项目的 `/api/stardust-config` 路径。

## 7. Stardust Realtime 会话

### 7.1 连接生命周期

```text
idle ──连接──> validating ──成功──> connecting ──session.updated──> connected
  ▲                  │                    │                         │
  │                  └──失败──────────────┴──失败──────────────────┤
  └──────────────────────────── 断开/关闭/错误 <───────────────────┘
```

要求：

1. 所有事件监听器必须在可能收到首次 `session.updated` 前完成注册。
2. 建立连接时发送一份完整 session 配置，不能先发送不含 tools 的配置再补发 tools。
3. 连接成功后按用户选择启用两种麦克风输入模式，并播放服务端音频。`Server VAD` 模式持续上送音频，由 Stardust 检测语音起止并创建响应；`Client VAD / Push to Talk` 模式只在用户按住按钮期间上送，松开后客户端依次发送 `input_audio_buffer.commit` 与 `response.create`。详细交互以 [语音输入布局与行为](./voice-input.md) 为准。
4. 两种模式均使用浏览器媒体轨道的 3A 能力：回声消除、噪声抑制、自动增益控制可分别配置；客户端记录浏览器实际应用的约束，实际值与请求值不同时产生可诊断 warning。
5. 麦克风 PCM 采集使用 `AudioWorklet`，不使用已废弃的 `ScriptProcessorNode`。第一版输入和输出统一使用 `24000Hz`、单声道、PCM16 little-endian；输入按 `100–200ms` 分片，播放器按 `24kHz PCM16 mono` 解码 `delta.audio`。
6. 用户主动断开、WebSocket 关闭或错误时，必须停止录音、停止音频播放并释放音频资源。
7. 连接错误显示在页面中；第一版由用户点击“重新连接”，不自动重放未完成的 function call。
8. 重连使用当前页面内存中的最新 session JSON，并保持当前模拟世界状态不变；重连本身不重置世界。

### 7.2 session.update JSON 编辑器

- 初始内容为项目内置的 Stardust session 示例对象；其 `model.tools` 必须直接包含 [内置 Realtime tools 契约](./tool-schemas.md#3-最终-session-中的完整-tools-定义) 中的 8 个完整定义，不能显示为空数组或只显示名称占位。
- 用户可以编辑完整 session 对象。
- 点击“格式化”只执行 JSON 解析和缩进格式化。
- 点击“应用”时只执行以下本地校验：
  1. 文本可被 `JSON.parse` 解析；
  2. 顶层值是非数组 JSON 对象。
- 不校验字段是否存在、模型名称是否有效、字段类型是否符合 Stardust schema、取值范围或组合是否合理。
- 不合适的配置由 Stardust/SDK 拒绝；页面原样显示错误，不擅自修改用户字段。
- 未连接时，“应用”更新当前页面内存中的待连接配置。
- 已连接时，“应用”调用等价于 `client.updateSession(runtimeSession, "stardust")` 的行为，并以 `session.updated` 作为成功依据。
- 页面在一次 `updateSession` 调用中提交完整的运行时副本；用户省略的普通字段仍按 SDK 的增量合并语义处理。`model.tools` 是唯一强制补全字段：为避免删除该键后遗留上一版用户 tools，用户未提供时在运行时副本中设为空数组，再执行第 7.3 节的同名剥离和内置 tool 注册。该补全不回写编辑器。
- 应用失败时保留编辑器内容和上一次已生效配置。
- 编辑器内容、已生效配置和错误在刷新后全部恢复初始值。

内置初始示例由以下 session 骨架和 `tool-schemas.md` 第 3 节的完整 tools 数组组成。下面使用 JSONC 注释避免复制并形成第二份 tools 定义；页面实际显示的内容必须是无注释的合法 JSON，并将 8 个完整对象展开在数组中。实现可以随 Stardust 协议升级示例值，但不得移除页面编辑能力：

```jsonc
{
  "model": {
    "provider": "tiwater",
    "name": "stardust-8.0",
    "ext_config": {
      "v8": {
        "enabled": true,
        "max_plan_steps": 4,
        "max_retry_count": 1,
        "enable_companion_narration": true
      }
    },
    "modalities": ["text", "audio"],
    "instructions": "你是一个人形机器人助手。请根据用户请求调用合适的机器人技能。",
    "tools": [
      // 按 tool-schemas.md 第 3 节依次展开 navigate_to、start_patrol、
      // follow_person、search_object、pick_and_place、hand_over、
      // execute_action、set_expression 的完整定义
    ],
    "tool_choice": "auto",
    "temperature": 0.8,
    "max_response_output_tokens": 4096
  },
  "speech": {
    "voice": "verse",
    "output_audio_format": "pcm16"
  },
  "hearing": {
    "input_audio_format": "pcm16",
    "turn_detection": {
      "type": "server_vad",
      "threshold": 0.05,
      "prefix_padding_ms": 300,
      "silence_duration_ms": 200
    }
  }
}
```

### 7.3 内置工具合并

机器人 8 个本地工具是系统能力。项目内置的缺省 session JSON 为了可见、可检查和可复制，必须显式包含全部 8 个完整定义；用户自行清空或删除 `model.tools` 时，运行时仍负责补齐。

内置 tools 的定义、去重、合并和注册顺序全部以 [内置 Realtime tools 契约](./tool-schemas.md#4-合并与注册) 为唯一事实来源。唯一允许的路径是：先从用户 session 副本中移除同名项，再通过 `addTool` 或行为等价且只注册一次的客户端工具接口注册 handler，由 SDK 在发送 session 时追加客户端 tools。

要求：

- 不得再手工把同一批内置定义追加到 `model.tools`，避免一份 tool 出现两次。
- 用户 JSON 中的非同名 tools 和 `tool_choice` 保持不变；未提供 `tool_choice` 时默认 `auto`。
- 用户编辑器内容不因运行时去重而改写；与内置定义 JSON 等价的同名项属于缺省展示，不产生 `builtin_tool_replaced` warning，只有内容不同的同名项才产生 warning。
- 客户端重建或重连时，在连接前重新完成一次注册；同一个客户端实例不得重复注册。
- 每个被内置定义替换的同名用户 tool 都在任务与事件面板显示一条 `warning` 级 `builtin_tool_replaced` 事件，包含 tool 名称；不使用阻塞 toast，也不只写浏览器控制台。

### 7.4 对话呈现

- 按实际发生顺序显示用户文本/转写、助手文本/转写、工具调用摘要和工具结果摘要。
- 流式文本和音频更新同一条助手消息，不重复创建消息。
- 用户打断助手时立即停止当前音频播放，并允许继续输入。
- 原始 Realtime 事件进入事件面板；连续大量 `response.audio.delta` 可聚合显示，避免淹没界面。
- 页面最多保留当前页面生命周期内最近 200 条可视事件；淘汰仅影响 UI，不写入任何存储。

## 8. 本地机器人技能契约

### 8.1 公共调用规则

工具名和参数字段是对 Stardust 暴露的稳定接口：

| 工具名 | 参数 | 必填规则 | 任务类型 |
|---|---|---|---|
| `navigate_to` | `location: string`，或 `x: number, y: number, theta?: number` | 地点和坐标二选一 | 有限 |
| `start_patrol` | `route: string` | `route` 必填 | 持续 |
| `follow_person` | `person: string` | `person` 必填 | 持续 |
| `search_object` | `object: string` | `object` 必填 | 有限 |
| `pick_and_place` | `object: string, target_location: string` | 两项均必填 | 有限 |
| `hand_over` | `person: string, object?: string` | `person` 必填；有多个手持物时 `object` 必填 | 有限、需人工确认 |
| `execute_action` | `action: string` | `action` 必填 | 有限 |
| `set_expression` | `expression: string` | `expression` 必填 | 有限 |

完整的 `type`、`description`、`parameters` JSON Schema、`required` 和 Stardust 执行元数据见 [内置 Realtime tools 契约](./tool-schemas.md)。

通过 `addTool` 注册的客户端 handler 在 SDK 收到 `response.output_item.done`、确认 function call output item 已完成且参数已收集完毕后触发。`response.function_call_arguments.done` 只用于累积和展示参数，不作为本地执行时机。执行器读取完成 item 中的 `name`、`arguments` 和 `call_id`。

所有工具共同遵循：

1. 使用 `call_id` 去重；缺少时使用 `response_id + item_id + name` 生成本页临时去重键。
2. 参数无法解析或不符合对应 tool schema 时不执行任务，返回 `status: failed` 和 `error_code: invalid_arguments`。
3. 非内置函数不属于本地执行器；记录 `ignored_unknown_tool` 应用事件但不执行、不发送 `function_call_output`，避免拦截用户配置的服务端工具。
4. 每次工具调用都在任务/事件区显示“收到、执行中、成功、失败或取消”。
5. 每个已识别调用只产生一次 `function_call_output`。
6. 输出通过 `conversation.item.create` 回传；回传后触发下一轮 `response.create`。
7. 有限任务在成功、失败或取消后回传最终结果。
8. `start_patrol` 和 `follow_person` 属于持续任务，成功启动后回传 `running`；该输出表示任务已被本地调度器接受，不表示任务永久成功。
9. 重复 `call_id` 记录 `ignored_duplicate_call` 应用事件，不重复执行，也不发送第二份输出。
10. 每个 handler 和参数解析边界必须捕获异常并转换为本节统一结构；不得让异常落入 SDK 默认的 `{ "error": "..." }` 包装。当前 SDK 无法在 handler 外拦截 JSON 解析错误时，应通过本地 Realtime 适配器或受控 SDK 补丁实现该契约。

统一输出结构：

```json
{
  "ok": true,
  "status": "succeeded",
  "tool": "navigate_to",
  "job_id": "job_xxx",
  "error_code": null,
  "message": "已到达厨房",
  "data": {}
}
```

输出字段规则：

- `ok`：`running` 或 `succeeded` 时为 `true`；`failed` 或 `cancelled` 时为 `false`。
- `status`：只取 `running`、`succeeded`、`failed`、`cancelled`。
- `error_code`：成功时为 `null`；失败或取消时为稳定的 snake_case 字符串。
- `tool`、`job_id`、`message`、`data` 始终存在。
- `awaiting_confirmation` 和 `ignored_*` 是本地任务/事件状态，不是 `function_call_output.status`。

第一版稳定错误码至少包含：

| `error_code` | 触发条件 |
|---|---|
| `invalid_arguments` | JSON 无法解析、必填参数缺失或参数组合违反 schema |
| `not_found` | 地点、路线、人物或物体不存在 |
| `unreachable` | 目标在地图外、禁入区或无法规划路径 |
| `robot_busy` | 所需资源已被不可抢占任务占用 |
| `object_not_graspable` | 物体自身不可抓取 |
| `no_free_hand` | 机器人没有空闲手 |
| `not_holding_object` | 交接时机器人未持有指定物体 |
| `target_not_placeable` | 目标不是可放置表面 |
| `person_lost` | 跟随人物不可见超过 5 秒，或交接等待期间人物离开、不可见或不可达 |
| `user_cancelled` | 用户取消交接或停止任务 |
| `superseded` | 可抢占任务被新的移动命令替代 |
| `world_reset` | 用户重置模拟世界导致任务取消 |
| `confirmation_timeout` | 交接等待人工确认超过 60 秒 |
| `planning_timeout` | 任一导航或重规划超过 2 秒墙钟时间 |
| `navigation_timeout` | 有限导航任务或内部导航阶段移动超过 60 秒模拟时间仍未到达 |
| `execution_failed` | 不能归入上述类型的本地执行失败 |

### 8.2 持续任务结束通知

`start_patrol` 和 `follow_person` 已经针对原始 `call_id` 回传一次 `running`，后续不得再次用同一 `call_id` 发送 `function_call_output`。

任务之后被停止、抢占或失败时，系统必须：

1. 更新本地任务和事件面板；
2. 向 Realtime conversation 追加一条 `role: system` 的 `input_text` 任务事件；
3. 不单独触发 `response.create`；模型在下一次正常响应时即可读取该状态；
4. Realtime 已断开时只记录本地事件，重连后不补发旧事件。

不触发 `response.create` 是第一版的刻意设计：任务与事件面板立即显示结束状态，但机器人不会主动生成语音播报；模型在用户下一次输入触发的正常响应中读取该 system task event。需要主动播报属于后续版本能力。

线上的 `conversation.item.create` 结构为：

```json
{
  "type": "conversation.item.create",
  "item": {
    "type": "message",
    "role": "system",
    "content": [
      {
        "type": "input_text",
        "text": "{\"type\":\"mock_humanoid.task_event\",\"job_id\":\"job_xxx\",\"tool\":\"start_patrol\",\"status\":\"cancelled\",\"error_code\":\"user_cancelled\",\"message\":\"日常巡视已停止\"}"
      }
    ]
  }
}
```

其中 `text` 反序列化后的任务事件为以下结构，不使用自然语言拼接作为机器契约：

```json
{
  "type": "mock_humanoid.task_event",
  "job_id": "job_xxx",
  "tool": "start_patrol",
  "status": "cancelled",
  "error_code": "user_cancelled",
  "message": "日常巡视已停止"
}
```

对话区把这类 system item 显示为任务事件，不伪装成用户消息或普通聊天气泡。

持续任务结束事件必须按下表取值：

| 结束原因 | `status` | `error_code` |
|---|---|---|
| 用户点击“停止当前任务” | `cancelled` | `user_cancelled` |
| 被新的移动命令抢占 | `cancelled` | `superseded` |
| 用户重置模拟世界 | `cancelled` | `world_reset` |
| `follow_person` 丢失人物超过 5 秒 | `failed` | `person_lost` |
| 巡逻或跟随目标无法规划路径 | `failed` | `unreachable` |
| 巡逻或跟随重规划超过 2 秒 | `failed` | `planning_timeout` |
| 其他本地执行异常 | `failed` | `execution_failed` |

### 8.3 `navigate_to`

用途：按地点名称或世界坐标执行点到点导航。

参数二选一：

```json
{ "location": "厨房" }
```

```json
{ "x": 4.2, "y": 1.8, "theta": 1.57 }
```

要求：

- 地点名称按完整名称匹配内置点位或当前页面创建的自定义点位；内置点位同时接受场景契约中的别名。
- 导航地点与可放置位置是互不通用的名称域；`location` 只匹配 `demo-scene.md` 第 4 节内置地点及页面自定义地点。传入“餐桌”“厨房台面”等仅属于第 5 节的名称时返回 `not_found`，需要前往该位置可使用坐标形式或先创建自定义位置点。
- `location` 不允许与 `x`、`y`、`theta` 中任一字段同时提供；坐标形式必须同时提供 `x/y`。违反任一规则时返回 `invalid_arguments`，不设置隐式优先级。
- 坐标使用米和弧度；`theta` 可省略，省略时保持路径终点朝向。
- 目标不存在、坐标在地图外或位于不可通行区域时返回失败。
- 使用 2D 占用栅格和导航图规划无碰撞路径。
- 每次有限导航或 `pick_and_place` 内部导航阶段的规划上限为 `2s` 墙钟时间，移动上限为 `60s` 模拟时间；超限分别返回 `planning_timeout` 或 `navigation_timeout`。持续巡逻和跟随不设置总移动超时，但其每次重规划仍受 `2s` 上限约束。
- 2D 地图和 3D 点云视图同时显示目标、完整规划线和已走轨迹。
- 到达位置容差为 `0.15m`；提供 `theta` 时朝向容差为 `10°`。

### 8.4 `start_patrol`

用途：按内置或当前页面创建的路线开始巡逻。

```json
{ "route": "日常巡视" }
```

要求：

- 路线名称必须匹配内置路线、别名或当前页面创建的自定义路线名称。
- 按路线点位顺序移动，在每个点位执行配置的停留时间。
- 默认循环执行，直到被新移动任务、“停止当前任务”或“重置模拟世界”终止。
- 启动成功即返回 `running`，输出中包含路线、点位数量和 `job_id`。
- 每次到达点位均写入事件面板。

### 8.5 `follow_person`

用途：跟随指定人物。

```json
{ "person": "张三" }
```

要求：

- 人物必须存在于模拟场景且当前可见。
- 人物沿预设的缓慢路线移动，机器人持续重规划并保持 `1.0m ± 0.25m` 跟随距离。
- 可见性由 2D 世界状态确定：机器人与人物中心距离不超过 `8m`，且两者中心连线不与 `demo-scene.md` 的固定障碍原始矩形相交时为可见；导航膨胀区不参与视线判定。
- 人物代理体之间不产生遮挡，3D 相机当前是否看见人物也不影响该判定。
- 人物短暂被障碍遮挡时，机器人前往其最后位置；人物不可见持续 5 秒后任务失败并停止。
- 成功启动即返回 `running`。
- 2D 和 3D 视图同时突出显示目标人物、人物轨迹和机器人当前规划线。

### 8.6 `search_object`

用途：在模拟环境中搜索指定物体并返回位置。

```json
{ "object": "红色杯子" }
```

要求：

- 在仍存在于场景且未被其他状态占用的物体中，按名称、别名、颜色和类别匹配。
- 搜索过程播放上半身扫描动作，并按 [内置演示场景契约](./demo-scene.md#8-搜索区域) 的稳定顺序检查候选区域。
- `search_object` 占用 `body_action`，不占用 `locomotion`；可与导航并行，行走时使用上半身扫描动画。
- 找到后在 2D 和 3D 视图中高亮物体 5 秒。
- 输出 `data` 至少包含 `object_id`、显示名称、`x`、`y`、`z` 和所在地点。
- 无匹配项时返回 `failed` 和可读原因。

### 8.7 `pick_and_place`

用途：抓取指定物体并放置到目标位置。

```json
{
  "object": "红色杯子",
  "target_location": "餐桌"
}
```

要求：

- 物体必须存在；`target_location` 只匹配 `demo-scene.md` 第 5 节的可放置位置规范名称或别名，不接受第 4 节普通地点。
- 参数命中普通地点但不是可放置位置时返回 `target_not_placeable`；完全未知的名称返回 `not_found`。
- 任务依次执行搜索、导航到抓取位、抓取、导航到放置位、放置。
- 内部搜索是 `pick_and_place` job 的阶段，不创建嵌套的 `search_object` 调用、`call_id` 或独立 job；它复用场景契约的区域索引，并由 `pick_and_place` 已持有的 `body_action` 资源播放扫描动画。
- 3D 视图显示弯腰/伸手、物体附着到手部、移动和释放动画；2D 视图显示移动路线。
- 抓取后物体状态变为 `held`，放置后更新为目标位置的 `placed`。
- 机器人没有空闲手、物体不可抓取、路径不可达或目标不可放置时返回失败。
- 失败发生在抓取之后时，机器人继续持有物体，事件和输出必须明确说明这一状态。

### 8.8 `hand_over`

用途：将机器人当前手持物递给指定人物并确认交接。

```json
{ "person": "李女士", "object": "欢迎卡" }
```

要求：

- 机器人必须持有物体，人物必须存在且可达。
- `object` 可省略；仅有一个手持物时自动选择它，有多个手持物时必须明确指定。
- 机器人前往人物附近、面向人物并伸出持物手。
- 页面显示模态确认层：“李女士是否已接收「物体名称」？”，提供“确认接收”和“取消交接”。
- 等待确认时任务状态为 `awaiting_confirmation`，不允许启动新的手部操作任务，但对话和表情仍可继续。
- 人工确认等待上限为 `60s`，模态层持续显示剩余秒数。超时后机器人收回手、继续持有物体，并回传 `status: cancelled, error_code: confirmation_timeout`。
- `awaiting_confirmation` 期间继续占用 `locomotion` 和 `manipulator`；新的移动、抓放、交接和身体动作返回 `robot_busy`，`set_expression` 仍可执行。
- 用户确认后，物体从机器人手中移除、追加到人物的 `held_objects`，3D 视图把它附着到人物的携带物锚点，函数输出 `succeeded`。
- 用户点击取消或停止任务时，机器人收回手并继续持有物体，输出 `status: cancelled, error_code: user_cancelled`。
- 等待确认期间人物变为不可见或不可达时，机器人收回手并继续持有物体，输出 `status: failed, error_code: person_lost`。
- 为保证该能力首次打开即可演示，初始世界中机器人左手持一张“欢迎卡”，右手空闲。

### 8.9 `execute_action`

用途：执行不接触人物和物体的身体动作。

```json
{ "action": "打招呼" }
```

第一版至少支持：`打招呼`、`点头`、`摇头`、`鞠躬`、`指向左侧`、`指向右侧`。

要求：

- 动作名称可接受内置别名，例如“挥手”映射为“打招呼”。
- 3D 中的宇树 G1 URDF 模型通过对应关节播放骨骼动画，任务栏显示动作名称和进度。
- 动作不会改变机器人世界坐标，也不会接触人物或物体。
- 未支持的动作返回 `failed`，不得用随机动画代替。

### 8.10 `set_expression`

用途：设置机器人面部表情或情绪。

```json
{ "expression": "开心" }
```

第一版至少支持：`中性`、`开心`、`难过`、`惊讶`、`思考`、`抱歉`。

要求：

- `set_expression` 将规范表情映射为 G1 脸部灯组的颜色和闪烁方式，并立即更新 3D 模型中脸部灯的发光效果。
- 灯效颜色、模式、周期和亮度以 [内置演示场景契约](./demo-scene.md#11-表情与-g1-脸部灯效) 为唯一事实来源；不得使用悬浮 HUD、表情气泡或虚构面部关节代替脸部灯效。
- 表情保持到下一次 `set_expression` 或模拟世界重置。
- 表情变化不阻塞导航、操作或对话。
- 世界状态和输出统一使用场景契约定义的 `FaceLightState`。成功输出的 `data` 固定包含规范化后的 `expression` 和 `face_light`；`face_light` 完整包含 `color`、`light_mode`、`intensity_min`、`intensity_max`、`current_intensity`、`period_ms`、`phase_elapsed_ms`，亮度统一使用 `0–1` 浮点数。
- 未支持的表情返回 `failed`，并保持原表情。

## 9. 任务调度与冲突规则

### 9.1 任务资源

| 资源 | 使用它的任务 |
|---|---|
| `locomotion` | `navigate_to`、`start_patrol`、`follow_person`、`pick_and_place`、`hand_over` |
| `manipulator` | `pick_and_place`、`hand_over` |
| `body_action` | `execute_action`、`search_object`、`pick_and_place`、`hand_over` |
| `face` | `set_expression` |

### 9.2 调度规则

- 同一资源同一时间只允许一个任务占用。
- function call 按完成事件到达顺序尝试获取资源，不建立等待队列。
- 资源互不冲突的调用可以并行，例如同一轮的 `set_expression` 与 `navigate_to`。
- 后到的调用与不可抢占任务冲突时立即返回 `failed + robot_busy`；与可抢占的直接移动任务冲突时按下一条规则处理。
- 新的直接移动命令会取消旧的 `navigate_to`、`start_patrol` 或 `follow_person`，然后启动新任务。
- `pick_and_place` 和 `hand_over` 执行中，新的移动、手部操作、`search_object` 或 `execute_action` 返回 `status: failed, error_code: robot_busy`，不得隐式打断可能持物或正在播放操作动画的任务。
- `execute_action` 可以与导航并行；如果动作会影响行走稳定性，动画只播放上半身版本。
- `search_object` 可与普通移动任务并行，但与 `execute_action`、`pick_and_place`、`hand_over` 互斥；后到者立即返回 `status: failed, error_code: robot_busy`，不排队。
- `set_expression` 始终可立即执行。
- “停止当前任务”取消占用 `locomotion` 或 `manipulator` 的任务；取消后保持已经发生的物体状态，不执行回滚魔法。
- 所有资源释放、取消和冲突均写入事件面板。

### 9.3 任务进度

- `navigate_to`：`已行进路径长度 / (已行进路径长度 + 当前剩余路径长度)`，限制在 0%–100%，重规划后 UI 进度不得倒退。
- `pick_and_place`：搜索 10%、前往抓取位 25%、抓取 15%、前往放置位 35%、放置 15%；阶段内按时间或路径比例插值。
- `hand_over`：前往人物 60%、伸手 30%、确认 10%；时间线为 `0% → 前往人物 → 60% → 伸手 → 90% → 等待确认 → 100%`。等待期间固定显示 90%，确认成功后更新到 100% 再结束，取消或超时则保持 90% 并以取消状态结束。
- `execute_action`：已播放时长 / 动画总时长。
- `search_object`：已检查候选区域数 / 总候选区域数。
- `start_patrol` 和 `follow_person` 为持续任务，不显示总百分比；分别显示当前点位/圈数和当前跟随距离。

## 10. 模拟世界

### 10.1 初始场景

第一版内置一个确定性的室内场景，每次刷新产生完全相同的初始状态。内置地点坐标、人物、物体、放置面、路线和别名以 [内置演示场景契约](./demo-scene.md) 为唯一事实来源；自定义位置点和路线是仅存在于当前页面的运行时叠加层。

场景必须覆盖：

- 地点导航和坐标导航。
- 循环巡逻和移动人物跟随。
- 可抓取、不可抓取和分布在不同区域的物体。
- 抓取后放置、初始手持“欢迎卡”和人工确认交接。
- 固定墙体、家具和不可通行区；2D 占用栅格与 3D 点云使用同一坐标系。

### 10.2 单一世界状态

2D、3D 和工具执行器不得维护互相独立的位置副本。它们必须订阅同一份内存世界状态：

```text
工具调用 ──> 任务调度器 ──> 世界状态更新
                               │
              ┌────────────────┼────────────────┐
              ▼                ▼                ▼
          2D 地图          3D 点云/机器人     任务与事件
```

世界状态至少包含：

- 机器人位姿、线速度、角速度、表情、场景契约定义的 `FaceLightState`、当前动画和左右手各自的手持物。
- 当前任务、任务进度、规划路径、已走轨迹和目标。
- 人物位姿、可见性、移动路线、`held_objects` 和携带物锚点。
- 物体位姿、类别、可抓取性、承载面和归属状态。
- 内置及自定义位置点、内置及自定义路线、路线的有序位置点 ID。

## 11. 2D 导航地图

### 11.1 显示内容

- 占用栅格或等价的墙体/障碍底图。
- 地点名称和点位图标。
- 机器人位置、朝向和足迹。
- 人物、可交互物体和目标高亮。
- 当前规划路径、已走轨迹、目标点和到达范围。
- 巡逻路线及当前巡逻点。

### 11.2 导航行为

- 使用 A* 或等价的确定性最短路算法。
- 机器人平面半径为 `0.30m`，规划时再增加 `0.10m` 安全边距，固定障碍总膨胀距离为 `0.40m`。
- 最大线速度为 `0.60m/s`，最大角速度为 `1.20rad/s`；接近终点时允许平滑减速。
- 世界仿真固定步长为 `50ms`；渲染帧率与仿真步长解耦。
- 行进速度在模拟时钟中保持可观察，不能瞬移。
- 路径变化必须通过平滑插值更新机器人位姿。
- 人物不写入 A* 占用栅格，规划路径及 2D/3D 规划虚线不得因人物位置改变；执行阶段把人物视为动态圆形障碍，机器人检测到前方人物时使用临时局部绕行点避让，越过后回归原规划路径。
- 机器人与人物的平面中心距离不得小于 `0.65m`（机器人半径 `0.30m`、人物代理半径 `0.25m`、额外安全间距 `0.10m`）。局部绕行产生的实际位姿只写入已走轨迹，不得追加或替换 `job.path`。
- 规划失败时机器人保持原位，界面说明不可达原因。
- 支持缩放、平移和“一键聚焦机器人”；障碍物和地图几何只读，位置点通过场景控制表单管理。

### 11.3 位置点与路线控制

- 场景控制面板的详细布局和交互以 [场景控制面板布局](./control-panel.md) 为准。
- 新位置点包含唯一名称、`x`、`y`、`theta`；名称去除首尾空白后不得为空或与现有地点重名，坐标必须为有限数并位于可通行区域，`theta` 使用弧度。
- 内置位置点和内置路线不可删除；自定义位置点和路线可删除。仍被路线引用的位置点必须先从相关路线移除，系统不得静默级联删除。
- 路线包含唯一名称和至少两个有序位置点，可同时引用内置和自定义位置点；执行时默认循环，并在每个点停留 3 秒。
- “前往”和“执行路线”调用与 Stardust tools 相同的验证、任务调度、资源抢占、路径规划和事件路径，但不产生 `function_call_output`。
- 自定义地点立即进入 `navigate_to.location` 名称域；自定义路线立即进入 `start_patrol.route` 名称域。
- 点击“重置模拟世界”或刷新页面时删除全部自定义位置点和路线，恢复内置定义；断开 Realtime 不删除它们。

## 12. 3D 点云与人形机器人视图

### 12.1 宇树 G1 URDF 模型

3D 地图中的机器人本体固定为宇树人形机器人 G1，并遵守以下资产与渲染契约：

- 使用 URDF 描述机器人 link、joint、visual origin 和 mesh 引用；不得以通用人形、简单胶囊体或其他机器人型号替代正常状态下的 G1。
- URDF 入口和本地资源目录以 [内置演示场景契约](./demo-scene.md#3-机器人初始状态与模型资产) 为唯一事实来源。
- URDF、mesh、材质和纹理随 Docker 镜像发布，浏览器运行时不得从公网 URL 下载机器人资产。
- 保持 URDF 的米制比例。加载后将脚底接触面校准到世界地面 `z=0`；世界 `theta=0` 时，G1 正面朝向世界 `+x`。
- 机器人在世界中的根位姿来自第 10.2 节的单一世界状态；URDF joint state 只负责步态、身体动作和操作动画，不维护第二份导航位姿。
- 动画使用 `/assets/robots/unitree-g1/semantic-map.json` 中集中维护的 G1 语义关节映射，把 `left_hand_link`、`right_hand_link`、头部、躯干和双腿映射到所引入 URDF 的实际 link/joint 名称。
- 所有关节动画必须限制在 URDF 声明的 joint limits 内；不得为了完成演示而修改 joint 名称、父子关系或限制值。
- 抓取时物体附着到语义关节映射指定的左/右手末端 link，释放或交接后解除附着并回到世界坐标。
- G1 语义渲染映射必须额外标识脸部灯对应的 mesh 或 material。`set_expression` 通过该目标的 emissive color、emissive intensity 和定时闪烁表达情绪，不使用悬浮 HUD。
- 闪烁动画使用模拟时钟驱动，同一表情在不同帧率下必须保持相同周期；切换表情时立即取消旧灯效定时器并从新模式的起始状态播放。
- 资产目录必须包含场景契约规定的 `asset-manifest.json`，记录 G1 URDF/mesh 的上游 URL、精确版本、许可证和文件校验值。若尚未选定可分发资产、许可不允许随镜像分发或清单不完整，交付视为阻塞，不得虚构元数据或静默换用其他模型。

URDF 或任一必需 mesh 加载失败时：

1. 3D 区域显示“宇树 G1 模型加载失败”和具体缺失资源；
2. 不回退成其他人形模型，以免掩盖资产问题；
3. 2D 地图、Realtime 对话和本地工具状态机仍可使用；
4. 依赖关节动画的 3D 表现标记为降级，但工具的世界状态结果保持一致。

### 12.2 显示内容

- 与 2D 场景一致的静态室内点云；生成源、固定随机种子和可降采样边界以场景契约第 2 节为准。
- 地面网格、坐标轴方向和米制比例提示。
- 可动画的宇树 G1 URDF 模型、人物代理体和可操作物体。
- 当前目标、规划路线和已走轨迹的 3D 覆盖层。
- 抓取、放置、交接、身体动作和 G1 脸部灯效表情。

### 12.3 视图交互

- 支持旋转、平移、缩放。
- 支持“自由视角”和“跟随机器人”两种相机模式。
- 导航时默认保持用户当前模式，不强制抢夺相机。
- 目标或搜索结果可一键聚焦。
- 切换到 2D 或隐藏 3D 时不得暂停世界仿真；重新显示后立即同步当前状态。
- 规划路径和已走轨迹覆盖层必须按任务复用 Three.js 对象；普通位姿、人物动画、进度或表情 revision 不得销毁并重建其 Geometry/Material。轨迹增长时允许更新 BufferAttribute，任务结束时统一释放对应 GPU 资源。
- 动画循环中的单帧异常不得永久终止后续帧。浏览器触发 `webglcontextlost` 时页面显示“3D 渲染上下文中断，正在恢复”，阻止默认永久丢失行为；收到 `webglcontextrestored` 后使用当前世界状态继续渲染，不重置任务。

### 12.4 一致性

- 2D 和 3D 使用同一个世界原点、米制单位和朝向约定。
- 默认 3D 相机下，世界 `+x` 与 `+y` 在屏幕上的方向分别与 2D 的向右、向上保持一致；Three.js 的 Y-up 坐标转换以 `demo-scene.md` 第 2 节为唯一规则，不得直接把世界 `y` 作为未翻转的 scene `z`。
- 同一动画帧中，两种视图的机器人平面位置偏差不得超过 `0.02m`。
- 规划路线在 3D 中投影到地面，其节点与 2D 路径节点来自同一数组。

## 13. 状态、空态与错误反馈

| 区域 | 初始/空态 | 忙碌态 | 错误态与恢复 |
|---|---|---|---|
| Realtime | “尚未连接” | “正在连接/断开” | 显示错误；允许重新连接 |
| 对话 | 提示连接后可说话或输入 | 流式文字和音量反馈 | 单条发送失败可重试，不自动重复工具调用 |
| 2D 地图 | 显示初始世界 | 路径和进度持续更新 | 规划失败保持原位并显示原因 |
| 3D 点云 | 加载 G1 URDF、mesh 和点云 | G1 动画/导航持续更新 | WebGL 或 G1 资产不可用时显示具体说明，2D、对话和工具状态机仍可使用 |
| session JSON | 显示内置示例 | 应用按钮显示处理中 | 定位 JSON 行列或显示 Stardust 错误 |
| 工具调用 | “暂无任务” | 工具名、参数摘要、阶段和进度 | 显示 error code、原因和当前物体状态 |
| 交接确认 | 不显示 | 模态层阻止重复手部任务 | 取消后机器人继续持物 |

事件面板不得只显示“失败”。错误至少包含：时间、工具名或事件类型、错误码、可读原因；有 `call_id`、`job_id` 时一并显示。

## 14. 无认证与无存储要求

### 14.1 无认证

- 访问根路径直接进入主页面。
- 不得出现登录、注册、验证码、用户菜单或 token 管理 UI。
- 不调用账号、组织、权限或用户资料接口。
- Stardust 连接使用第 6 节的容器环境配置，不要求用户提供凭据。

### 14.2 无存储

应用不得使用以下机制保存业务状态：

- 数据库或远程存储 API。
- 写入容器文件系统。
- `localStorage`、`sessionStorage` 或 IndexedDB。
- 用 cookie 保存 session、配置、对话、任务或世界状态。
- Service Worker 离线业务缓存。

允许浏览器和 Web 服务器使用正常的静态资源 HTTP 缓存，但缓存不得影响模拟世界和业务状态重置。

刷新页面后必须：

1. 断开旧 Realtime 会话并释放音频资源；
2. 清空对话、事件、JSON 草稿、调用去重集合和任务；
3. 恢复内置 session 示例；
4. 恢复初始机器人、人物、物体、路线和表情；
5. 回到未连接状态，不自动恢复上一连接。

## 15. 可用性与性能要求

- 首屏应在常规开发机本地打开后 3 秒内显示页面骨架和 2D 场景；Realtime 连接时间不计入首屏。
- 3D 视图目标帧率为 30 FPS；低性能设备可降低点数，但不得改变世界坐标和任务结果。
- 单次导航动画中 2D 与 3D 的可见状态更新延迟应小于 100ms。
- 所有按钮必须有文字或可访问名称；连接状态不能只依赖颜色表达。
- 破坏性较强的“重置模拟世界”需要确认；断开连接和停止任务不需要确认。
- 用户拒绝麦克风权限时，文本对话和所有模拟工具仍可使用。
- 第一版正式支持当前及前一个主要版本的桌面 Chrome 和 Edge；Firefox、Safari 和移动浏览器为尽力兼容，不作为阻塞验收目标。
- 非 `localhost` 部署必须通过 HTTPS 提供页面并使用 WSS 连接 Stardust，保证浏览器允许麦克风权限；Stardust 网关必须允许部署页面的 Origin 和 WebSocket Upgrade。
- 运行时配置接口与页面同源；若部署架构引入反向代理，必须透传 `/api/runtime-config`、静态 G1 资产和 WebSocket 所需头部，不得缓存运行时配置响应。

## 16. 验收标准

### 16.1 启动与页面

- [ ] 使用仅包含必需环境变量的 Docker 命令可以启动单容器服务。
- [ ] 打开根路径不出现任何认证流程。
- [ ] 缺少 `group_id` 或 `robot_id` 时页面可用，但明确阻止连接。
- [ ] `/api/runtime-config` 符合第 6.4 节结构、返回 `no-store`，且不泄露其他环境变量。
- [ ] 2D 地图和 3D 点云显示同一初始机器人位置。
- [ ] 默认相机下，前台、厨房、会议室、展示区及机器人在 2D/3D 中具有一致的上下和左右关系，不出现南北镜像。
- [ ] 正常状态下 3D 机器人由内置宇树 G1 URDF 和配套 mesh 加载，不出现通用人形替代模型。

### 16.2 Realtime

- [ ] 连接时 URL 含正确的 `group_id` 和 `robot_id`。
- [ ] 设置抽屉首次打开以及点击“恢复本页初始值”后，缺省 session JSON 的 `model.tools` 均显式展开 8 个本地 function tools，不是空数组或名称占位。
- [ ] 缺省 JSON 中的 8 个 tools 与 `tool-schemas.md` 完全一致，连接时各发送一次且不产生替换 warning；内容不同的同名用户 tool 被替换并产生 warning，非同名 tools 被保留。
- [ ] `builtin_tool_replaced` warning 显示在任务与事件面板并包含被替换的 tool 名称，不仅输出到控制台。
- [ ] 同一客户端重复应用 session 配置不会重复注册或发送内置 tools；新建客户端连接前恰好注册一次。
- [ ] 用户可以通过语音和文本获得模型回复，并听到实时音频。
- [ ] `Server VAD` 模式连接后持续上送音频，session 中 `hearing.turn_detection.type` 为 `server_vad`，客户端不主动 commit 或创建语音响应。
- [ ] `Client VAD / Push to Talk` 模式的 session 中 `hearing.turn_detection` 为 `null`；按下按钮开始上送，松开后只提交一次 `input_audio_buffer.commit` 和 `response.create`。
- [ ] 两种语音模式均能分别配置回声消除、噪声抑制和自动增益控制，并在事件面板记录浏览器实际应用值及不一致 warning。
- [ ] 麦克风输入和助手音频均按 `24000Hz`、单声道、PCM16 little-endian 处理，输入分片和输出播放无明显变速或声道错误。
- [ ] 用户打断时当前助手音频停止。
- [ ] 已连接时应用合法 JSON 会发送新的 `session.update`，并显示 `session.updated` 结果。
- [ ] 用户删除 `model.tools` 后应用配置，运行时仍显式提交空的用户 tools 数组并只合并 8 个内置 tools，不残留上一版用户 tool。
- [ ] 同名 tool 剥离或内置 tool 注入失败时不发送不完整的 `session.update`，保留上一份已生效配置并在事件面板显示具体错误。
- [ ] 非法 JSON 显示解析位置，不发送更新。
- [ ] 语法合法但业务不合理的 JSON 不被前端字段校验拦截；下游错误原样可见。

### 16.3 工具调用

- [ ] `navigate_to` 使用地点名称和坐标两种参数均可到达目标。
- [ ] 页面可新增一个合法位置点并点击“前往”；2D 地图立即显示该点，机器人通过正常导航任务到达。
- [ ] 重名、非有限坐标、地图外或障碍内的位置点被明确拒绝且不写入世界状态。
- [ ] `navigate_to` 同时提供地点和坐标、缺少 `x` 或缺少 `y` 时返回 `invalid_arguments`。
- [ ] `navigate_to` 使用 `location + theta` 时返回 `invalid_arguments`。
- [ ] 模型侧未拒绝非法参数时，本地校验仍拒绝 `location+x/y`、`location+theta`、仅 `x` 和仅 `y`，且不创建导航任务。
