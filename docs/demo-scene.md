# mock-humanoid 内置演示场景契约

状态：Draft  
版本：0.7  
日期：2026-07-21

## 1. 目的

本文档定义第一版内置室内场景的稳定名称、别名和初始状态，是导航、跟随、搜索、抓放、交接、动作及表情测试数据的唯一事实来源。

页面刷新或点击“重置模拟世界”后必须恢复本文件定义的状态。场景只读，不提供编辑或持久化能力。

通道与可达性契约：

- 中央隔断的北侧与南侧都必须保留可通行绕行通道；实现不得增加未在本表声明、会封死通道的固定障碍。
- 以 `0.05m` 栅格分辨率和 `0.40m` 总膨胀距离计算时，前台、展示区、会议室入口、厨房及充电位均处于同一可达连通域。
- 巡逻闭环的四段“前台 → 展示区 → 会议室入口 → 厨房 → 前台”均必须可规划；地图或膨胀参数变更时必须由自动化可达性测试重新验证。
- 3D 点云不使用外部预制 PCD。它由本节相同的墙体与障碍表面程序化生成，采用固定随机种子 `mock-humanoid-v1`；性能模式可以确定性降采样，但不得改变轮廓、坐标或障碍占用关系。

资产契约：

- URDF 入口固定为 `/assets/robots/unitree-g1/g1.urdf`。
- 当前可分发资产取自宇树官方仓库 `https://github.com/unitreerobotics/unitree_ros`，固定 commit `aa0f5c68b5aba347bad409e71b6430407da758d7`，上游文件为 `robots/g1_description/g1_29dof.urdf`，许可证为 BSD-3-Clause；运行时不得自动跟随上游分支更新。
- URDF 引用的 mesh、材质和纹理统一放在 `/assets/robots/unitree-g1/` 下，并使用可由同一 Web 服务解析的相对路径。
- 资产目录必须包含 `asset-manifest.json`，记录上游仓库 URL、精确 tag/commit、许可证标识与许可证文件路径，并列出 URDF、mesh、材质和纹理的 SHA-256；未选定可再分发的上游版本或清单不完整时，G1 资产交付视为阻塞。
- 实现不得只提交 URDF 而遗漏 mesh，也不得在清单完成前虚构来源、版本或许可证。
- 语义关节映射固定为 `/assets/robots/unitree-g1/semantic-map.json`。至少包含 `left_hand_link`、`right_hand_link`、`head_joints`、`torso_joints`、`leg_joints` 和 `face_light_target`，每个值必须解析到该 URDF 的真实 link、joint、mesh 或 material。
- G1 动画配置属于代码资产，但必须通过上述语义映射引用，不得在动作实现中散落硬编码 joint 名称。
- 语义渲染映射必须标识 G1 脸部灯对应的 mesh 或 material，供表情系统修改 emissive 颜色和强度。
- 2D 导航仍采用需求文档定义的 `0.30m` 平面半径和 `0.10m` 安全边距，不直接从 URDF visual 包围盒推导碰撞半径。

## 11. 表情与 G1 脸部灯效

G1 通过脸部灯组的颜色、亮度和闪烁节奏表达表情。以下映射是第一版模拟器的稳定视觉契约：

### 11.1 `FaceLightState`

世界状态、3D 渲染器和 `set_expression` 输出统一使用以下结构，不得另设 `mode`、`intensity` 等同义字段：

```json
{
  "color": "#E5E7EB",
  "light_mode": "steady",
  "intensity_min": 0.55,
  "intensity_max": 0.55,
  "current_intensity": 0.55,
  "period_ms": null,
  "phase_elapsed_ms": 0
}
```

字段规则：

- `color`：CSS 十六进制 RGB 颜色。
- `light_mode`：只取 `steady`、`breathe`、`blink`、`double_blink`。
- `intensity_min`、`intensity_max`、`current_intensity`：闭区间 `0–1` 的浮点数，并满足 `intensity_min <= current_intensity <= intensity_max`。
- `steady` 必须满足 `intensity_min === intensity_max === current_intensity`，且 `period_ms` 为 `null`。
- 其他模式的 `period_ms` 为正整数；`current_intensity` 和 `phase_elapsed_ms` 由模拟时钟持续更新。
- 切换表情时 `phase_elapsed_ms` 重置为 `0`；`breathe` 的零相位取 `intensity_min`，`blink` 和 `double_blink` 的零相位取 `intensity_max`。

`set_expression` 成功输出的 `data` 固定为 `{ "expression": "规范名称", "face_light": FaceLightState }`，其中 `face_light` 是切换完成时世界状态的快照。

### 11.2 表情映射

所有亮度值均为闭区间 `0–1` 的浮点数：

| 规范名称 | 接受的别名 | 颜色 | 灯效模式 | 周期 | 参数 |
|---|---|---|---|---:|---|
| 中性 | 默认、平静、正常 | `#E5E7EB` 柔白 | `steady` 常亮 | — | 亮度 `0.55` |
| 开心 | 高兴、微笑、愉快 | `#22C55E` 绿色 | `breathe` 呼吸 | `1600ms` | 亮度在 `0.35–1.00` 间平滑变化 |
| 难过 | 悲伤、伤心 | `#3B82F6` 蓝色 | `breathe` 慢呼吸 | `2400ms` | 亮度在 `0.20–0.60` 间平滑变化 |
| 惊讶 | 吃惊、震惊 | `#FACC15` 黄色 | `double_blink` 双闪 | `900ms` | 亮度 `0–1.00`，每周期两次短闪，单次 `120ms` |
| 思考 | 思索、疑惑 | `#06B6D4` 青色 | `blink` 闪烁 | `1200ms` | 亮度 `0–0.85`，亮 `420ms`、灭 `780ms` |
| 抱歉 | 歉意、道歉 | `#A855F7` 紫色 | `breathe` 慢呼吸 | `2200ms` | 亮度在 `0.25–0.70` 间平滑变化 |

### 11.3 灯效波形

令 `t = phase_elapsed_ms % period_ms`，模式按以下确定性规则计算 `current_intensity`：

- `steady`：始终等于 `intensity_max`。
- `breathe`：`intensity_min + (intensity_max - intensity_min) * (1 - cos(2πt / period_ms)) / 2`，从最暗平滑过渡到最亮再返回最暗。
- `blink`：`0 <= t < 420ms` 时取 `intensity_max`，`420ms <= t < 1200ms` 时取 `intensity_min`。
- `double_blink`：`0–120ms` 和 `240–360ms` 取 `intensity_max`；`120–240ms` 和 `360–900ms` 取 `intensity_min`。区间均左闭右开。

`blink` 和 `double_blink` 的区间长度是当前映射表的固定契约；若将来修改其周期，必须同时给出新的完整区间，不按比例隐式缩放。

渲染要求：

- `steady`、`breathe`、`blink`、`double_blink` 是稳定的内部模式名。
- 灯效通过 G1 脸部灯目标 mesh/material 的 emissive 属性呈现，不使用悬浮 HUD、Emoji 或聊天气泡。
- 别名在执行前归一化为规范名称；世界状态保存规范名称、颜色、模式、周期和当前相位。
- 表情没有自动恢复计时器，保持到下一次 `set_expression` 或世界重置。
- 页面刷新或世界重置后恢复“中性”：柔白色、`0.55` 亮度、常亮。
