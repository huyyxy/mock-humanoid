# mock-humanoid 场景控制面板布局

状态：Draft
版本：0.1
日期：2026-07-22

## 1. 设计原则

场景控制面板用于当前页面内存中的位置点和路线管理，不承担固定障碍、人物、物体或地图几何编辑。所有手动执行命令复用 Realtime tools 的模拟引擎路径。

## 2. 页面结构

```text
右侧栏
┌──────────────────────────────────┐
│ [对话] [场景控制] [任务与事件]   │
├──────────────────────────────────┤
│ 位置点                           │
│ ┌名称────┐ ┌X──┐ ┌Y──┐ ┌θ──┐   │
│ └────────┘ └───┘ └───┘ └───┘   │
│                         [新增]   │
│ • 前台       (1.50, 2.00) [前往]│
│ • 演示点     (3.20, 4.10) [前往]│
│                              [删]│
├──────────────────────────────────┤
│ 路线                             │
│ 名称 [________________]           │
│ 位置点 [前台________▼] [加入]    │
│ 1 前台       [↑][↓][移除]        │
│ 2 演示点     [↑][↓][移除]        │
│                     [保存路线]   │
│ • 接待路线  2 点 [执行] [删除]   │
└──────────────────────────────────┘
```

## 3. 交互契约

| 输入 | 行为 |
|---|---|
| 新增位置点 | 校验名称、数值和可通行性；成功后立即显示在列表及 2D 地图 |
| 前往 | 启动与 `navigate_to` 相同的有限导航任务 |
| 删除位置点 | 仅允许删除自定义点；被路线引用时显示错误，不删除 |
| 加入路线 | 将当前选择的位置点追加到草稿末尾，可重复经过同一点 |
| 上移/下移/移除 | 只修改路线草稿的有序点列表 |
| 保存路线 | 名称唯一且至少两个点时加入当前世界 |
| 执行 | 启动与 `start_patrol` 相同的循环持续任务 |
| 删除路线 | 仅允许删除自定义路线；运行中的任务继续使用启动时快照 |

错误显示在场景控制面板顶部，不使用阻塞弹窗。执行成功或失败同时进入任务与事件区域。

## 4. 状态与响应式

- 内置项显示“内置”标签且无删除按钮；自定义项显示删除按钮。
- 位置点或路线为空时保留表单并显示空状态说明。
- 机器人移动资源繁忙时，“前往”或“执行”走现有抢占/冲突规则，不在按钮层复制判断。
- `<1024px` 时控制面板随右侧栏纵向排列；表单字段允许换行，所有按钮保持可达。
- 重置或刷新删除自定义项；断开 Realtime 不改变面板数据。
